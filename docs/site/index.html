Broken docs links should fail CI — not your users.

Linkfail checks Markdown http(s) links in GitHub Actions: fail the PR, leave a comment, ship an HTML + SARIF report, open a weekly Issue, and ping Slack.

Get started in 60s GitHub

The problem

Docs rot quietly. A renamed page, a dead blog post, a 404 badge — none of them fail your build until a customer hits the link. Linkfail makes “links still work” a first-class CI check.

60-second setup

  1. Buy a Polar license and add secret LINKFAIL_LICENSE_KEY.
  2. Run npx linkfail init or copy examples/linkfail.yml into .github/workflows/.
  3. Push — PRs fail + comment; Monday cron opens an Issue; reports land in linkfail-out/.

Features

🚫

CI gate

Fail the job when any checked link is broken, timed out, or errored.

📅

Weekly Issue

Schedule or manual runs open/update a digest Issue with the full report.

💬

PR comment

Upsert a report comment on pull requests so reviewers see dead links instantly.

📊

HTML report

Self-contained dashboard in linkfail-out/report.html — upload as an artifact.

🔎

SARIF

Optional Code Scanning SARIF so broken links show in the GitHub UI.

🔔

Webhook

Slack-compatible incoming webhook — soft-fail if the hook is down.
